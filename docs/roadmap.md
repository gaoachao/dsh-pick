# dsh-pick 开发路线图

## M0：工程初始化

- [x] 独立的 TypeScript / ESM / Cordis 插件工程。
- [x] `dsh.bundle`、GitHub 安装构建脚本和 tarball 分发配置。
- [x] `PickContext` v1 类型草案与手写示例。
- [x] 类型检查、编译、Cordis 加载与卸载检查、GitHub Actions CI。

## M1：选中元素并提交反馈

- [ ] 在本地开发页面显式开启 picker；悬停高亮、点击选中、Esc 退出。
- [ ] 采集 selector、标签、有限文本、视口、元素边界和指定样式。
- [ ] 在 DSH 客户端展示上下文与用户反馈，确认后发到选定会话。
- [ ] 增加浏览器通信协议、运行时校验、来源检查、消息大小限制。
- [ ] 页面导航、目标失效、会话切换及卸载时正确取消和清理。

验收：在真实本地页面完成一次「选中 → 反馈预览 → 用户确认 → 正确会话收到信息」，不调用模型也能验证传输内容。未开启时不干扰页面操作。

## M2：React 源码定位

- [ ] 提供开发期适配器，为组件标注可验证的源码位置。
- [ ] 显示工作区相对文件路径、行号、组件名及映射来源。
- [ ] 处理组件包装与无法解析的位置；明确展示信息缺失。

验收：用已知源码位置的示例项目验证映射；生产构建不包含 picker 和源码元数据。

## M3：修复前后验证

- [ ] 保存经用户确认的截图产物与视口条件。
- [ ] 在相同路由、视口和可重建状态下再次观测。
- [ ] 并列显示修复前后结果，允许用户继续提出反馈。

验收：通过窄屏溢出的固定案例证明改动生效；目标状态无法恢复时标记不可比较。

## 后续探索

多元素反馈、更多开发框架适配、键盘交互验收和可分享的问题包。在 M1 跑通前保持单包结构。
