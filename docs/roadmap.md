# dsh-pick 开发路线图

[English README](../README.md) · [中文 README](../README.zh-CN.md) · [设计文档](design.md) · [开发说明](development.md)

设计文档定义目标行为；本页记录实现进度。M0 已完成，M1 的浏览器基础能力已可通过本地演示验证。

## M0：工程初始化

- [x] 独立的 TypeScript / ESM / Cordis 插件工程。
- [x] `dsh.bundle`、GitHub 安装构建脚本和 tarball 分发配置。
- [x] `PickContext` v1 类型草案与手写示例。
- [x] 类型检查、编译、Cordis 加载与卸载检查、GitHub Actions CI。
- [x] 设计文档、英文默认 README 和中文版入口。

## M1：选中元素并加入会话草稿

- [ ] 验证固定 DSH 版本的客户端打包、会话插槽与公开草稿插入接口。
- [x] 提供 React + Vite 开发期接入和跨窗口握手，生产构建剔除 picker。
- [x] 在目标页面显式开启 picker；悬停高亮、点击选中、Esc 退出。
- [x] 采集 selector、标签、有限文本、视口、元素边界和指定样式。
- [ ] 在 DSH 客户端预览上下文与反馈，经用户确认加入绑定会话的草稿。
- [ ] 保留已有文本、引用块和附件，处理版本冲突并防止重复插入。
- [x] 增加浏览器通信协议、观测字段运行时校验、来源检查、消息大小限制。
- [ ] 页面导航、目标失效、会话切换及卸载时正确取消和清理。

已验证：浏览器页面失效检查、Esc/断开清理与页面刷新后重连。尚未接入 DSH 会话作用域及插件卸载；本地演示不能替代这两项验收。使用方式见 [浏览器预览指南](browser-preview.md)。

验收：在真实本地页面完成「选中 → 反馈预览 → 加入草稿 → 用户通过原生输入框发送」，正确会话收到与预览一致的信息；不调用模型也能验证传输。通过设计文档中的 M1 验收矩阵，未开启时不干扰页面操作。仅提供复制反馈的降级模式不算 M1 完成。

## M2：React 源码定位

- [ ] 扩展开发期适配器，为 JSX 元素标注可验证的源码位置。
- [ ] 显示工作区相对文件路径、行号、组件名及映射来源。
- [ ] 处理组件包装与无法解析的位置；明确展示信息缺失。
- [ ] 校验路径属于绑定工作区，处理 HMR 版本失效。

验收：用已知源码位置的示例项目验证映射；生产构建不包含 picker 和源码元数据。

## M3：修复前后验证

- [ ] 确定并接入浏览器截图提供方及 DSH 附件接口。
- [ ] 保存经用户确认的截图产物与视口条件。
- [ ] 在相同路由、视口和可重建状态下再次观测。
- [ ] 并列显示修复前后结果，允许用户继续提出反馈。

验收：通过窄屏溢出的固定案例证明改动生效；目标状态无法恢复时标记不可比较。
