# dsh-pick 设计文档

[English README](../README.md) · [中文 README](../README.zh-CN.md) · [开发说明](development.md) · [路线图](roadmap.md)

状态：设计草案。更新日期：2026-09-08。当前实现仅达到 M0；下文描述计划中的行为，不代表 0.0.1 已提供这些能力。

## 1. 产品目标

让开发者在本地页面上指出「改这里」，把修改意图和可核对的页面观测一起带入 DSH 会话，减少口头描述 UI、寻找组件和反复补充上下文的成本。

典型场景：开发者在 390 px 宽的设置页发现账户菜单溢出，选中菜单并输入「修复窄屏溢出，同时保留键盘操作」。DSH 收到反馈、目标元素、视口和有限样式；能够可靠定位源码时，再附上文件位置。修复后，开发者回到相同条件复测。

首版成功标准是：用户能辨认自己选中的目标，知道将加入草稿的内容，并把它交给正确的会话；插件不替用户直接发送消息或启动代码修改。

## 2. 范围与阶段

| 阶段 | 交付内容 | 明确边界 |
| --- | --- | --- |
| M0：当前 | 可加载的 Cordis bundle、构建、CI、`PickContext` 类型草案 | 没有浏览器功能；类型尚无运行时校验 |
| M1：反馈闭环 | 本地 React + Vite 页面接入、元素点选、反馈预览、加入 DSH 草稿 | DSH Web 与目标页面在同一台电脑、同一浏览器；一次一个目标元素 |
| M2：源码定位 | 开发期 JSX 标注、工作区相对路径、映射来源 | 信息不足时省略位置；不把猜测当作源码映射 |
| M3：修复验证 | 可选截图、状态复现说明、修复前后对照 | 无法恢复目标状态时明确标为不可比较 |

M1 不覆盖任意线上网站、跨域 iframe 内部、Shadow DOM 内部、跨浏览器连接、多元素批量选择或自动修复。接入方式先支持显式配置的开发项目，不要求安装浏览器扩展。只有顶层文档中的普通 DOM 元素属于首版选择范围。

## 3. 用户流程与交互

1. **接入项目。** 开发者在目标应用配置 Vite 适配器并启动开发服务器；在 DSH 中配置目标 URL，绑定当前工作区。适配器显式允许该 DSH origin。
2. **开始点选。** 用户在选定会话点击 Pick，插件记录会话和工作区身份，在用户操作中打开目标页面，并建立连接。
3. **选择元素。** 悬停显示边框、标签和尺寸；点击锁定元素；Esc 退出选择。只有选择模式拦截点击，退出后立即恢复页面操作。滚动和窗口变化时更新高亮位置。
4. **描述与预览。** DSH 面板展示页面路径、视口、目标摘要、采集字段及可用的源码位置。用户在 DSH 面板输入反馈，可删除可选观测字段或重新选择；页面文本不能充当用户反馈。
5. **加入草稿。** 用户点击「加入草稿」后，插件重新检查连接、会话和元素状态，再插入反馈与观测摘要。保留已有草稿、引用块和附件；成功后标记本次选择已加入，重复点击不再插入。
6. **正常发送。** 用户通过 DSH 原有输入框继续编辑和发送。模型执行、工具授权和消息排队继续由 DSH 处理。

状态流为 `idle → connecting → picking → reviewing → attaching → attached`。取消返回 `idle`；观测失效进入 `stale`，要求重新选择；连接失败进入 `disconnected`，允许重连。只有 `reviewing` 状态可以加入草稿。

会话或工作区切换会取消待提交选区并关闭其连接；不把旧选区自动转交给新会话。刷新或卸载插件也会清理待提交状态。已加入原生草稿的内容由 DSH 管理。

## 4. 系统划分

```text
目标应用：React + Vite                DSH Web
┌──────────────────────┐             ┌────────────────────────┐
│ 开发期适配器          │             │ Pick 入口与会话绑定     │
│ picker：高亮、观测    │ ←─────────→ │ 连接管理、校验、预览    │
└──────────────────────┘ postMessage └────────────┬───────────┘
                                                 │ 用户加入草稿
                                      ┌──────────▼───────────┐
                                      │ DSH 原生输入框与发送  │
                                      └──────────┬───────────┘
                                                 │ 用户发送
                                      ┌──────────▼───────────┐
                                      │ 会话日志 → 模型与工具 │
                                      └──────────────────────┘
```

保持单仓库、单 npm 包，按运行环境组织模块：

| 模块 | 职责 | 代码状态 |
| --- | --- | --- |
| `src/index.ts` | Cordis host 入口，后续组合配置和所需服务 | 已有加载日志 |
| `src/shared/` | 上下文类型、后续消息协议、运行时校验和文本格式化 | 仅有 `types.ts` |
| `src/client/` | DSH 客户端入口、Pick 面板、连接与会话状态、输入框适配 | 待实现 |
| `src/picker/` | 目标页面中的 DOM 选择、高亮、有限观测 | 待实现 |
| `src/adapters/vite/` | 开发期注入 picker；M2 增加源码标注 | 待实现 |

M1 的观测通过浏览器传入原生草稿，不需要另建持久化服务或注册模型工具。目标页面不能请求 host 执行命令、读取文件或提交会话。

DSH 客户端入口实施时再增加 `dsh.client`、`exports["./client"]` 和对应浏览器构建。它必须遵循 DSH 的客户端注册及打包协议；当前 `tsc` 输出的 host ESM 不能直接充当客户端 bundle。客户端入口与目标应用的 picker 分别构建，后者不依赖 DSH 客户端运行时。依据：[客户端模块](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/client-modules)。

DSH 使用 React UI 插槽。Pick 入口通过会话范围的插槽扩展，在作用域内获取会话与输入框能力，不替换整个输入组件、不导入内部实现。事件和插槽注册随 Cordis 生命周期释放；手动创建的 DOM 监听、连接与观察器由 disposer 清理。依据：[UI 插槽](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/slots)。

Vite 适配器只在开发服务器中注入页面脚本；生产构建不包含 picker 或源码元数据。拟提供 `dsh-pick/vite` 导出，具体参数和兼容版本在 M1 接入验证后确定，目前不能作为安装 API 使用。依据：[Vite 插件 API](https://vite.dev/guide/api-plugin.html)。

## 5. 浏览器连接与消息协议

### 连接方式

首版采用 DSH 打开的独立目标窗口与 `window.postMessage` 通信。相比在 DSH 内嵌 iframe，它保留目标应用的顶层页面环境；相比浏览器扩展，它能复用已有的开发期接入。

连接流程：DSH 在用户点击时保存目标窗口引用，生成一次性 `connectionId`；向配置的精确 target origin 发送连接请求。目标适配器检查 DSH origin 及 `event.source === window.opener`，回复协议版本和本次页面加载的 `pageInstanceId`。DSH 同时检查回复的 origin、窗口引用和连接标识，握手完成后才允许点选。

双方在后续消息中持续检查 origin、source、连接标识和协议版本，不使用 `"*"` 作为 target origin。连接标识用于区分连接，不替代 origin/source 检查。DSH 的登录凭据、会话 ID 和工作区绝对路径不传给目标页面。`postMessage` 的跨窗口能力与校验要求依据 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)。

目标 URL 由用户显式配置；M1 仅接受本机开发服务。窗口被拦截、COOP 导致 opener 隔离、适配器未启动或握手超时均显示连接失败，不自动修改目标应用的浏览器隔离策略。首版不提供静默降级到任意网络代理的路径。

### 消息外层与上下文分离

以下是拟议协议，尚未加入现有 TypeScript 类型：

```ts
interface BridgeEnvelope<T> {
  protocolVersion: 1;
  connectionId: string;
  pageInstanceId: string;
  requestId: string;
  sequence: number;
  type: 'pick:start' | 'pick:result' | 'pick:validate'
    | 'pick:valid' | 'pick:stale' | 'pick:cancel';
  payload: T;
}
```

握手是建立上述信封前的独立消息。每个方向的 `sequence` 单调递增；不接受旧连接、旧页面、重复响应或不匹配的请求。`pick:result` 携带本次 `pickId` 与页面观测；`pick:validate` 引用该 `pickId`，用于加入草稿前复核。插件为每个请求设置超时，关闭连接会取消所有在途请求。

DSH 客户端另存 `PickBinding = { workspaceId, sessionId, connectionId, pageInstanceId, pickId }`，工作区和会话身份来自 DSH，不能采用目标页面声明的值。只有绑定仍有效时，才能将页面观测与用户反馈合成为 `PickContext`。

## 6. 观测数据与格式

现有协议草案见 [`src/shared/types.ts`](https://github.com/gaoachao/dsh-pick/blob/main/src/shared/types.ts)，手写样例见 [`examples/pick-context.ts`](https://github.com/gaoachao/dsh-pick/blob/main/examples/pick-context.ts)。`PickContext` 是一次观测快照；它不代表可长期复用的定位器，也不是可信浏览器输入。

| 字段 | 内容与约束 | 阶段 |
| --- | --- | --- |
| `schemaVersion`、`capturedAt` | 固定版本与 ISO 8601 采集时间 | M1 |
| `feedback` | 用户在 DSH 面板输入的修改请求 | M1 |
| `page.url` | 去掉凭据、查询参数和 fragment 的页面 URL | M1 |
| `page.viewport` | CSS 像素尺寸与 `devicePixelRatio` | M1 |
| `element.selector`、`tagName` | 当前页面中的定位候选与标签 | M1 |
| `element.text` | 可选的有限可见文本，不采集表单值 | M1 |
| `element.bounds` | `getBoundingClientRect()` 的视口坐标，使用 CSS 像素 | M1 |
| `element.styles` | 已声明的 computed-style 白名单 | M1 |
| `source` | 可验证的工作区相对路径、行列、组件名、映射来源 | M2 |
| `screenshot` | 经确认的独立截图产物引用 | M3 |

浏览器结果进入 DSH 时按精确 schema 重建对象：丢弃未定义字段，验证类型、枚举、有限数值和 URL。采集端先限制数据量，接收端再次校验；不能通过 TypeScript 类型断言替代验证。宽高和 DPR 必须有效，边界坐标允许负值，以保留超出视口的真实情况。

拟定首版预算为：单条桥接消息最多 32 KiB，反馈最多 4,000 字符，文本和 selector 各最多 2,000 字符，每个样式值最多 256 字符。反馈超限时提示用户编辑，不静默截断；可选观测被截断时在预览中明确显示。selector 超限或无法生成可靠候选时要求重新选择，不把截断后的 selector 当作有效定位器。具体预算随真实页面测试调整。

采集范围不包括完整 HTML、整页 DOM、输入框值、`contenteditable` 内容、Cookie 或存储数据。提取文本时遍历并跳过表单和编辑节点，不能对包含它们的祖先直接读取整段 `innerText`。样式只允许当前 `PickStyleProperty` 中的 10 个属性。可见文本仍可能含业务内容，因此用户必须能在预览中移除该字段。

URL 处理会丢失 query/hash 路由状态。M1 不声称能够自动复现这类页面；用户可在反馈中补充必要步骤。内部页面失效判断仍应对完整 location 的变化敏感，但完整 URL 不进入消息载荷。

selector 优先考虑唯一且稳定的测试标识或 ID，再尝试有限祖先路径；生成时进行 CSS 转义并检查是否唯一指向当前元素。它只提供定位线索，不能证明跨 HMR、跨页面版本仍指向同一对象。

## 7. 接入 DSH 草稿与模型

输入框适配是独立模块，提供插件内部的 `attachPick(binding, context)` 操作，负责确认会话、检查输入状态、插入文本和返回成功或失败；这不是现有 DSH API 的名字。

必须满足四个条件：插入发生在绑定的会话；不覆盖用户并发编辑；保留已有引用块和附件；同一次 `pickId` 最多插入一次。输入框忙碌或草稿版本改变时返回可重试状态，用户复核后重试，不自动排队到其他会话。

核对过的 DSH 输入契约提供 `draftRev`、输入阶段和带版本的文本插入请求。`setDraft` 会重建整份文本，不能用 `setDraft(oldDraft + pickText)` 实现追加，否则会丢失引用块的结构信息。`slash/input-insert-text` 的 span 使用 detect 坐标，不能用普通草稿字符串长度计算。依据：固定提交的 [输入契约](https://github.com/deepseek-ai/deepseek-harness/blob/c389f96bf3a9b6807cb71ed6bdad5849be0df6d8/packages/client/ui-conversation/src/client/contract/input.ts) 与 [输入实现](https://github.com/deepseek-ai/deepseek-harness/blob/c389f96bf3a9b6807cb71ed6bdad5849be0df6d8/packages/client/ui-conversation/src/client/input/facade.ts)。

M1 首先做最小接入验证，确认目标发布版本中可用的公开插入路径及正确的会话作用域。已有契约不等于插件已经能可靠调用它。若无法在公开接口上保留草稿结构，提供「复制反馈」作为明确标识的临时功能，不使用私有编辑器接口；此时「自动加入已有草稿」仍是未完成项，不能将 M1 标记完成。

插入内容采用固定格式：用户反馈在前，时间、页面和元素观测以带标签的 JSON 数据块附后。所有页面文字按数据序列化，不解释为工具调用或高优先级指令；格式化器应处理反引号等分隔符，避免页面文本突破数据块。预览与实际插入共用一份格式化结果，避免用户审阅后发生隐式补充。

M1 不注册模型工具、不增加常驻系统提示词，也不通过隐藏通道追加上下文。用户发送后，内容沿 DSH 原生会话日志进入模型，重放与分叉沿用已记录的用户消息。插件只在内存保存未加入草稿的临时状态；已加入草稿及已发送内容的保存由 DSH 负责。依据：[DSH 架构](https://deepseek-harness.github.io/deepseek-harness/en/reference/) 与 [Conversation 子系统](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/conversation)。

## 8. 选区有效性与生命周期

picker 持有被选中的实际 DOM 引用，同时记录页面实例、完整 location 的本地状态、视口和采集结果。加入草稿前，DSH 通过 `pick:validate` 请求目标页面检查：

- 页面实例和连接仍匹配，目标元素仍 `isConnected`。
- selector 仍唯一指向该元素，视口、边界和所采集字段没有变化。
- 导航、HMR 或其他已知页面版本变化没有使观测过期。

检查失败或超时则要求重新选择和审阅，不能悄悄替换成更新后的观测。对比的是实际采集字段；不声称能识别所有应用内部状态变化。已加入草稿的内容始终是标注采集时间的静态快照，插件不保证它在用户稍后发送时仍与页面一致，也不自动改写原生草稿。

高亮按动画帧合并更新，鼠标移动不向 DSH 持续发送 DOM 数据；只有选中和明确的复核请求才产生观测消息。监听器、观察器和悬浮层按连接生命周期创建，取消时全部移除。目标页刷新会生成新的 `pageInstanceId`，旧回调不得恢复选区或插入草稿。

## 9. React 源码定位（M2）

开发期适配器为可定位的 JSX 宿主元素建立元数据，包含项目根目录下的相对文件路径、原始行列和映射来源；有充分依据时提供组件名。UI 要区分「元素的 JSX 定义位置」与「组件的使用位置」，不能把组件包装层猜成用户实际要修改的位置。

优先采用明确的编译期 instrumentation。只有已有 DOM 到编译产物的关联时，才通过 source map 回溯原始位置；source map 本身不能从任意 DOM 元素推导组件。首版源码定位不依赖 React Fiber 等未公开内部字段。

适配器配置的项目根目录必须与 DSH 绑定工作区匹配。host 使用源码位置前再检查规范化路径和真实路径，限制在该工作区内；拒绝绝对路径、越界路径和符号链接逃逸。未经校验的页面元数据不能直接成为读文件参数。

第三方组件、动态生成节点、缺失 source map 或 HMR 版本不匹配时省略 `source`，在预览中显示「源码位置不可用」。生产构建需要单独验证不会残留注入脚本、源码路径或标记属性。

## 10. 修复前后验证（M3）

截图是可选的独立产物。普通页面脚本不具备可靠的浏览器截图能力，需另行接入经过验证的浏览器截图提供方；提供方、截图授权和产物生命周期在 M3 确定。没有可用提供方时，DOM 反馈仍可使用，不生成伪截图或虚构产物路径。

用户确认截图范围后，提供方生成产物，DSH 通过原生附件能力接入。`PickContext.screenshot.path` 只引用已建立且可解析的产物，不接受目标页面任意指定 host 文件路径，也不把 base64 图片塞进文本上下文。裁剪时明确区分 CSS 坐标与图像像素，并验证 DPR、滚动位置和实际截图尺寸。

比较记录包含页面路径、视口、滚动位置、目标定位信息和用户提供的复现步骤。修复后尽量在同样条件下重新选择并截图；登录状态、动态数据、query/hash 路由或交互状态无法恢复时，显示「不可比较」及原因。截图差异只能辅助视觉检查，不能单独证明键盘交互或业务逻辑正确。

## 11. 异常与恢复

| 情况 | 用户可见行为 | 内部处理 |
| --- | --- | --- |
| 适配器缺失、弹窗受阻或握手失败 | 显示连接原因与重试入口 | 取消在途请求，不采集 |
| 未支持的目标，如 iframe 内部 | 提示当前选择范围限制 | 不尝试跨文档读取 |
| 协议版本不兼容 | 提示更新匹配版本 | 拒绝建立连接 |
| 消息来源错误、格式错误或超限 | 对当前连接显示简短错误；无关来源不打扰用户 | 丢弃消息，不进入草稿 |
| 页面刷新、选区失效或观测变化 | 标记过期，要求重新选择 | 清除旧页面的待提交结果 |
| 会话或工作区切换 | 结束本次点选 | 使旧绑定失效，忽略迟到响应 |
| 输入框忙碌或版本冲突 | 保留预览，允许复核后重试 | 不覆盖草稿，不重复插入 |
| 找不到源码位置 | 显示位置不可用 | 保留可用 DOM 观测 |
| 截图失败或状态无法复现 | 保留文本反馈，标记缺失或不可比较 | 不伪造产物或比较结果 |

调试日志默认仅记录阶段、错误码和必要标识，不记录反馈正文、页面文本或截图内容。

## 12. 验收与实施顺序

### M1 验收矩阵

| 场景 | 通过条件 |
| --- | --- |
| 本地示例页面的正常流程 | 选中、预览、加入草稿，随后由用户发送；正确会话收到与预览一致的内容 |
| 已有文本、引用块和附件 | 插入后全部保留；并发输入导致的版本冲突可恢复 |
| 重复点击、乱序响应、旧页面回调 | 同一 `pickId` 不重复插入；旧连接不影响当前会话 |
| 滚动、缩放、窄屏和高 DPR | 高亮与真实元素一致，坐标与单位正确；视口变化使旧观测失效 |
| 导航、HMR、元素移除、会话切换 | 明确提示取消或失效，不能把旧信息加入新会话 |
| 表单与异常页面文本 | 不包含输入值；超限可见；反引号和指令式文本保持数据形式 |
| 错误来源、错误版本、异常载荷 | 接收端拒绝，不修改草稿 |
| 退出选择、关闭目标页、卸载插件 | 页面点击恢复，悬浮层、监听器和在途请求被清理 |
| 生产构建 | 目标应用不含 picker 和开发期元数据 |

输入框接入验证、桥接握手和端到端页面交互必须在真实浏览器及固定 DSH 版本上完成。协议边界、格式化和乱序处理适合自动化测试；纯类型检查不能代替这些验收。首版流程不依赖模型返回结果，可以在不调用模型的情况下验证上下文传输。

M2 使用已知 JSX 文件位置的示例项目验证映射、组件包装、缺失信息、越界路径及生产构建剔除；M3 使用固定的窄屏溢出案例验证截图坐标、修复对照和不可比较状态。

建议实施顺序：先验证 DSH 客户端打包和草稿插入，再实现 Vite 注入与握手，然后补点选、预览、校验和生命周期，最后跑完整 M1 验收。后续任务状态统一维护在 [路线图](roadmap.md)。

### 实施前需要验证的接口

| 问题 | 决策要求 |
| --- | --- |
| 目标 DSH 发布版本能否通过公开接口安全插入草稿？ | 用真实引用块、附件和并发编辑验证；无法满足时保留复制模式并标记 M1 未完成 |
| 客户端契约与所选 npm 版本是否匹配？ | 同时固定 DSH、客户端依赖和浏览器 bundle 构建方式，记录集成结果 |
| Vite / React 适配范围如何确定？ | 从一个固定版本的示例项目开始，验证后再声明支持范围 |
| 截图来自哪个提供方、如何保存？ | M3 接入前确认附件接口、尺寸语义和清理规则 |

这些验证不会改变当前骨架的功能声明；新增入口、依赖和 API 只在对应实现完成后发布。
